# 객체 지향 프로그래밍이란?(Object-Oriented Programming)
- 프로그램을 여러 객체들의 협력으로 구성하는 프로그래밍 방식
- 객체는 데이터와 기능을 함께 가진 하나의 개별 단위이다.
- 게임에서는 Player, Enemy, Item, Weapon, Inventory 같은 개념을 객체로 표현할 수 있다.
- 객체 지향은 코드를 현실의 개념에 가깝게 나누어 이해하기 쉽게 만든다.
- 프로젝트가 커질수록 역할을 나누고, 코드를 재사용하고, 수정/확장하기 쉬운 구조를 만드는 데 도움이 된다.

## 객체 지향 프로그래밍을 사용하는 이유
- 클래스 단위로 역할을 나누어 코드 구조를 정리할 수 있다.
- 이미 만든 클래스를 재사용하거나 상속, 다형성, 인터페이스로 확장할 수 있다.
- 기능 변경이 생겼을 때 관련된 객체만 수정하면 되도록 만들 수 있다.
- 여러 개발자가 작업할 때 각자 맡은 객체나 기능 단위로 나누어 작업하기 좋다.

## AI 에이전트 개발 환경에서 객체 지향 프로그래밍의 중요성
- AI 에이전트는 사용자의 요청에 따라 코드를 읽고, 수정하고, 확장한다.
- 코드의 역할이 객체 단위로 명확하게 나뉘어 있으면 AI가 구조를 이해하기 쉽다.
- 하나의 클래스가 너무 많은 일을 하게 되면 AI도 작업 범위를 판단하기 어려워진다.
- 객체 지향적으로 설계된 코드는 사람뿐 아니라 AI도 읽기 쉽고 작업하기 쉬운 코드가 된다.
- 코드 구조가 명확하면 AI가 불필요하게 많은 파일을 읽지 않아도 되므로 토큰 사용량도 줄일 수 있다.

### 용어 정리
1. 클래스(Class)
- 객체를 만들기 위한 설계도
- 객체가 가질 변수와 함수를 정의한다.
- 일반 C# 클래스는 new 키워드로 객체를 생성할 수 있다.

2. 객체(Object)
- 클래스를 바탕으로 실제로 만들어진 개별 대상
- 클래스에 정의된 변수와 함수를 독립적으로 가진다.
- 같은 클래스로 여러 객체를 만들 수 있고, 각 객체는 서로 다른 상태를 가질 수 있다.

3. 컴포넌트(Component)
- 유니티 게임오브젝트에 붙어서 특정 기능을 담당하는 객체
- Transform, SpriteRenderer, Rigidbody2D 등등과 직접 만든 MonoBehaviour 스크립트
- 게임오브젝트는 여러 컴포넌트를 조합해서 기능을 갖는다.

4. MonoBehaviour
- 유니티에서 제공하는 컴포넌트용 기본 클래스
- 직접 new 키워드를 사용하지 않고, 게임오브젝트에 AddComponent()로 붙여 사용한다.
- Start(), Update() 같은 유니티 이벤트 함수를 사용할 수 있다.
- 인스펙터뷰에서 SerializeField나 public 변수를 통해 값을 정하고 참조를 연결할 수 있다.

5. 일반 객체(비 MonoBehaviour 객체)
- MonoBehaviour가 아닌 일반 C# 객체
- new 키워드로 직접 객체를 생성해서 사용한다.
- 주로 데이터 관리, 규칙 계산, 상태 관리 등에 사용한다.
- System.Serilizable을 사용하면 인스펙터뷰에서 편집 가능하게 활용할 수 있다.

6. 스크립터블 오브젝트(ScriptableObject)
- 유니티에서 제공하는 에셋 형태의 객체
- 게임오브젝트에 붙는 컴포넌트가 아니라 프로젝트에 저장되는 데이터 에셋이다.
- 캐릭터 능력치, 아이템 정보, 몬스터 데이터처럼 여러 곳에서 공유할 데이터를 관리할 때 유용하다.
- 인스펙터뷰에서 편집할 수 있다.

### 객체 지향 프로그래밍의 4대 핵심 요소
1. 캡슐화(Encapsulation)
- 객체의 데이터와 기능을 하나로 묶고, 외부에서 직접 함부로 바꾸지 못하게 보호하는 것
- 외부에서는 필요한 경우에만 함수나 프로퍼티를 통해 접근한다.
- 접근 제어자(public, private, protected), Getter/Setter, 프로퍼티를 사용한다.
- 잘못된 값 입력을 막아 안정성을 높일 수 있다.
- 기본적으로 멤버 변수는 private으로 두고, 외부에 제공할 함수만 public으로 공개하는 것이 안전하다.

2. 상속(Inheritance)
- 클래스 사이에 부모-자식 관계를 만들어 공통 코드를 재사용하는 것
- 부모 클래스의 변수와 함수를 자식 클래스가 물려받아 사용할 수 있다.
- class 자식클래스명 : 부모클래스명
- 공통 기능은 부모 클래스에 작성하고, 자식 클래스는 자신만의 기능을 추가하거나 확장한다.
- 코드 재사용과 구조 정리에 도움이 되지만, 부모-자식 관계가 자연스러울 때 사용한다.

3. [다형성(Polymorphism)](./Polymorphism.md)
- 같은 부모 타입으로 여러 자식 객체를 다룰 수 있게 하는 것
- 같은 함수 호출이라도 실제 객체 타입에 따라 다르게 동작할 수 있다.
- 부모 타입 변수로 자식 객체를 담아 사용할 수 있다.
- 상속과 virtual-override, 인터페이스를 통해 구현할 수 있다.
- 유연하고 확장성 있는 코드를 만들 수 있다.

4. [추상화(Abstraction)](./Abstraction.md)
- 복잡한 대상에서 필요한 공통점과 핵심 정보만 뽑아내는 것
- 중요한 부분만 보여 주고, 불필요한 세부 내용은 숨긴다.
- 클래스를 설계할 때 어떤 데이터와 기능이 필요한지 정리하는 과정이다.
- 필요하면 추상 클래스나 인터페이스를 활용한다.
- abstract-override, 인터페이스를 통해 공통 구조와 사용법을 설계할 수 있다.
