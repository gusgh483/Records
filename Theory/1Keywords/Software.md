# 소프트웨어(SoftWare)

## 정의
- CPU(하드웨어)가 두뇌라면 소프트웨어는 두뇌에  입력되는 명령어 모음이라 할 수 있다. <br> (하드웨어: 명령을 수행하는 일꾼 / 소프트웨어: 명령 하달자)
- 소프트웨어가 하드웨어에 명령을 하달하여 수행한다.
	- 하드웨어와 소프트웨어의 차이
	
	| 구분 | 하드웨어 | 소프트웨어 |
	| --- | --- | --- |
	| 개념 | 물리적인 형태를 가진 기계 장치 | 형태가 없는 명령어와 프로그램 |
	| 특징 | 만질 수 있고 무게가 있음 | 만질 수 없고 데이터로 존재함 |
	| 열할 | 물리적인 작업 실행 및 데이터 처리 | 하드웨어에 동작 방법과 순서 지시 |
	| 수정 | 변경이나 교체가 어렵고 비용이 듦 | 파일 수정 및 업데이트가 비교적 쉬움 |
	| 예시 | CPU, 메모리, 본체, 모니터, 키보드 | 윈도우(OS), 앱, 웹 브라우저, 게임 |

## 특성
- 소프트웨어의 본질적 특성
	- 무형성 (Intangibility): 물리적인 형태나 질량이 없으며 논리적인 코드와 데이터의 집합으로 존재
	- 복제성 (Duplicability): 하드웨어와 달리 원본이 있으면 적은 비용으로 무한대에 가까운 복제와 배포가 가능
	- 변경성 (Mutability): 사용자 요구사항이나 기술 발전에 따라 지속적으로 기능을 추가하고 수정하기 용이
	- 순응성 (Adaptability): 운영체제(OS), 하드웨어, 네트워크 등 변화하는 IT 환경 속에서도 정상 작동하도록 적응하고 변형 가능
	- 비가시성 (Invisibility): 구조가 외부로 명확하게 드러나지 않고 복잡한 내부 코드 속에 숨어 있어 관리가 어려움<br>
  


- 물리적 제품과의 차별점
	- 비마모성 (Non-wearing out): 사용한다고 해서 물리적으로 닳거나 수명이 다하지는 않으나, <br> 환경 변화나 오류(Bug)로 인해 지속적인 유지보수 필요.
	- 비제조성 (Non-manufacturing): 공장에서 찍어내듯 생산하는 것이 아니라, 인력과 지식 노동을 통해 '개발(Engineering)' 됨.
	- 견고성 (Robustness): 코드의 작은 수정 하나가 시스템 전체에 치명적인 영향을 미침.

## 위기 (Software Crisis)
- 원인
	- 소프트웨어 자체의 복잡성 증가
	- 전문 인력 부족
	- 경영층의 인식 부족
	- 일관성 있는 방법론 및 지원 도구의 문제
	- 소프트웨어 개발 생산성 저하
- 결과
	- 품질 저하와 유지보수의 어려움 증가
	- 빈번하게 명세와 불일치 발생
	- 제품의 신뢰도 결여
	- 초과 비용 발생
	- 개발 일정이 계획보다 지연
